## Token 预算优化方案（PLN-037）
- 用户提供 2 局 5 人 live 实测：Total 494,542 / Input hit 38,784 / Input miss 190,514 / Output 265,244。
- **成本拆解**（deepseek-v4-flash：hit ¥0.02/M、miss ¥1/M、output ¥2/M）：Output 占 ~73.5% 成本、输入 miss ~26.4%、hit 几乎为 0 → **削减输出是头号杠杆**，其次提升缓存命中率。
- **缓存命中率低根因**：`ai_agent.act()` 每轮重建大 system_prompt，记忆/局势/行动上下文位于中部且逐轮变化，DeepSeek 前缀缓存（完整单元匹配）在变化点断裂 → 仅稳定段（角色+人格+规则 ~17%）命中。5 agent 无共享规则前缀。
- **输出巨大根因**：deepseek-v4-flash 默认 thinking=high（reasoning token 计入输出且项目从未传 thinking/reasoning_effort）；speak 双重调用（speech_cache 预生成 + act 二次修正）；claims 每条发言异步 LLM 提取；无 max_tokens 上限。
- **方案要点**（详见 `docs/plans/token-budget-optimization-plan.md`）：P0 按 action_type 分级控制 thinking（vote/night/nominate=disabled、speak/defense=low）+ max_tokens 上限 + reasoning≤30字 + speak 草稿复用跳过二次 LLM + claim 批量/规则优先；P1 system prompt 重构为「稳定规则层 + 稳定长上下文 + 逐次变化尾部」三层 + 跨 agent 公共规则前缀；P2 解析 hit/miss/reasoning_tokens + 基准脚本 + 单测。目标：total≤30万、命中率≥50%、输出占比≤40%。

## AI 玩家 Agent 原生重构方案（PLN-038）
- **用户论断（认同）**：当前 AI 玩家不是 agent，只是「集中式调度 + 单次无状态 LLM 调用」的上下文/提示词工程产物。用户要求重构为独立 agent：自己的 loop、目标=赢游戏、发言/投票/私聊/策略标准化为工具/skill、记忆由 agent 自主按原则维护文件。
- **架构判断**：方案定调为「事件驱动的受控自主 Agent」而非完全自由 agent——回合顺序/合法性/胜负判定留在引擎（`RuleEngine`/`AgentActionLegalContext`），信息隔离红线不变（一切世界信息过 `InformationBroker`，记忆落盘也须过隔离层），白天发言禁 gather。
- **四层改造**：决策（引擎唤醒 agent loop：observe→deliberate→act→remember）、行动（Tool 注册表 speak/vote/nominate/night_action/defense_speech/private_message，复用 dialogue_manager ToolDef 范式，JSON 兜底）、世界感知（只读工具 observe_state/query_public_log/query_players，prompt 瘦身）、记忆（工具 append_memory/read_memory/reflect，落盘 data/agents/{player_id}/）。
- **阶段 A→D**：A 行动工具化（act 返回 tool_calls）→ B 策略先行小 loop（think→act）→ C 记忆工具化（替换 _reflection_threshold 硬阈值）→ D 世界感知查询化（稳定 tool schema 前缀，协同 PLN-037 缓存命中 16.9%→60%+）。
- **落地**：与 PLN-037 并作 Alpha 1.3 统筹实施（先 P0 输出削减，再 A/B，最后 C/D）。文档 `docs/plans/agent-native-redesign-plan.md` 已过 doc 门禁（70 md PASS）。尚未改代码，待用户确认。
