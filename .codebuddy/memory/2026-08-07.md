## ✅ PLN-040 T3.5 mock fallback 根因修复（待用户确认后提交）

- **根因**：PLN-039 三层前缀把"当前需要执行的动作类型"从 system 移到 user 末条，`MockBackend._extract_action_type` 仍只扫 system_prompt → 提取失败 → 所有动作返回默认 speak 决策 → `normalize_decision` 判非法 → **vote/nomination 100% fallback**（fallback_rate 57%，mock 审计摘要 `invalid_vote_decision`/`invalid_nomination_target`）。
- **修复**：`mock_backend.py` 改为扫描 `system + messages` 拼接文本。修复后 vote 返回 `decision:true`、nomination 返回 `nominate+target`；**fallback_rate 57%→2.4~11.9%**。新增 6 单测 `tests/test_llm/test_mock_action_type.py`。
- **关键发现**：修复后重跑标定实验 polarized Δ 反转负（-0.002）——**mock 返回固定合法决策绕过 `_select_nomination_target`/threshold 判断路径，tendency 影响的决策阈值在 mock 的 LLM 模拟路径下永不被消费**。修复前 Δ+0.03 部分是 fallback 随机噪声假象。
- **方案 3（落地）**：标定脚本开启 `AI_FAST_LOW_VALUE_ACTIONS=1` 复现 live 本地判定路径（`local_low_value_decision` 消费 threshold）→ **polarized Δ+0.0092 / mixed Δ+0.0226（差异化重新可测，纯真实信号）**。注意不得同时设 `AI_FORCE_PROGRESS_ACTIONS=1`（会强制 vote=True 覆盖 tendency）。
- **结论**：决策阈值类差异化的量化验证，mock 下必须走本地判定路径（与 live 一致），不能依赖 mock 的 LLM 模拟路径。RPT-015 已补 §6。全量 ruff 0 + 回归通过。任务 19 已登记 PROGRESS。
